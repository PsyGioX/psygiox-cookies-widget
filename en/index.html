Cookies under control — in real time

PGX Cookies Widget is a lightweight cookie-consent widget for the EU, US, Russia and the rest of the world. It sees every cookie the moment it is written, keeps the extras out until consent, and is fully configurable through one API.

features

What ordinary cookie banners don’t do

A banner that only asks is half the job. PGX also watches what the page actually writes, and acts on it.

◉

Cookie Radar — tracking in real time

The widget wraps document.cookie and listens to the Cookie Store API: every new, changed and deleted cookie appears in the log instantly — with category, vendor and size. Embed the live panel into your own admin or debug page.

PsyCookies.on('cookie', e => console.log(e.type, e.name, e.category));
PsyCookies.live.mount('#cookie-monitor');
⛨

Cookie Guard

No consent — no cookie. Analytics and ad cookies are blocked as they are written, and ones that show up from outside are deleted.

Laws of different countries

Four profiles — EU, US, Russia and World — with the right consent model, defaults and wording for each.

Scripts and iframes on consent

Mark a tag and it runs only after the category is allowed. Blocked iframes get a neat placeholder.

Consent Mode v2 and GPC

Google Consent Mode v2 and dataLayer events out of the box. A Global Privacy Control signal switches off “sale and sharing” in the US profile.

✓

Consent receipts

An anonymous receipt (id, policy version, categories) goes to your endpoint — evidence that consent was given.

#

Verifiable builds

Minified scripts and styles, SHA-256 sums, SRI (sha384), a reproducible archive and immutable versioned URLs. CI fails if the dist folder drifts from the sources. Themes light/dark/contrast, RTL, focus trap and reduced-motion are built in too.

i18n

Translations without a heavy parser

No ICU parser: the browser does the plurals, numbers, dates and lists. A pack is a single line, and your own language takes one call.

// a pack is just data; the order of loading does not matter
PsyCookies.i18n.add('de', {
  'banner.title': 'Ihre Privatsphäre ist uns wichtig',
  'banner.reject@us': 'Reject non-essential', // region variant
  'live.total': {                           // Intl.PluralRules
    one:   '{n} Cookie auf dieser Seite',
    other: '{n} Cookies auf dieser Seite'
  }
});
PsyCookies.i18n.set('de');   // or data-lang="auto"
PsyCookies.i18n.t('live.total', { n: 5 });

install

By link or by archive

Pick what suits you. Every path comes with hashes for verification.

  1. Paste the tag as the first script in . The version folder never changes, so the SRI hash stays valid.
  2. Add links to your documents and (optionally) the region from the server. The CSS and language packs load automatically.
  3. Put data-pc-open on any link to reopen the settings.
<script src="https://psygiox-cookies-widget.vercel.app/widget/dist/v1.0.1/psygiox-cookies.min.js"
        integrity="sha384-9jUYYzRkKgBKz1+WwvWS2ghO7OvoST4w02+yGFwHW6QBwmCMuKlHMfMgPtFOgm3f" crossorigin="anonymous"
        data-policy="/cookies" data-privacy="/privacy"></script>

api

Configure with attributes, code or JSON

The same options everywhere. Later sources win: defaults → PsyCookiesConfig → data-attributes → init()/configure() → remote JSON.

<!-- 1. attributes -->
<script src=".../psygiox-cookies.min.js"
  data-region="eu" data-lang="auto" data-theme="dark"
  data-position="bottom-right" data-guard="enforce"
  data-tokens='{"accent":"#7dff2e","radius":"20px"}'
  data-receipt="/api/consent"></script>

// 2. code
PsyCookies.configure({
  categories: [{ id: 'chat', labels: { en: { title: 'Chat' } } }],
  cookieRules: [{ match: '^chat_', category: 'chat' }]
});
// 3. runtime
PsyCookies.open('live');              // banner | settings | live
PsyCookies.set({ analytics: true });
PsyCookies.allowed('marketing');       // boolean
PsyCookies.theme.set('dark');
PsyCookies.cookies.list();           // name, category, status…

// 4. events
PsyCookies.on('consent', e => console.log(e.granted, e.revoked));
PsyCookies.on('violation', e => report(e.name));
addEventListener('psygiox-cookies:change', console.log);

faq

Questions and answers

Is this legal advice?
No. The widget implements widely accepted practices for each region, with conservative defaults, but your texts, periods and the list of cookies depend on your site. Have a lawyer review them.
How is the region chosen?
By the browser time zone: Russian zones → ru, Europe → eu, US zones → us, everything else → world (the strict opt-in model). It is a heuristic, so pass the real region from the server in data-region when it matters.
Can I use it on a commercial site?
Yes, GPL-3.0 allows it. If you change the widget and distribute the result, publish your changes under the same licence. The readable sources are served from /widget/src/. This is a summary, not legal advice.
What exactly does Cookie Guard see?
Cookies available to page scripts: those written through document.cookie and those that appear in the cookie jar (found by Cookie Store events and a light check). HttpOnly cookies are invisible to any script — they must be managed on the server. Values are never shown or stored.
Does it work with Google Tag Manager?
Yes. Consent Mode v2 signals are sent before GTM loads (keep the widget first), and the psygiox_consent dataLayer event is available as a trigger.
What does this website store?
Only the necessary cookie psygiox_consent (your choice, up to 6–12 months) and the offline cache of the PWA. No analytics, no third-party trackers, no advertising, no requests to other sites. Cookies created in the demo are written by you and live only in your browser.
